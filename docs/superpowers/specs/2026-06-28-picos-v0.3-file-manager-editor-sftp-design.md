# picos v0.3 File Manager, Editor, and SFTP Design

## Goal

Make `picos` useful as a daily terminal OS console, not only a system dashboard. v0.3 adds a file workspace, DOS-like file commands, a safe text editing flow, and a provider abstraction that can later support SFTP without changing the user experience.

## Product Principle

The feature should optimize for real developer workflows:

- Inspect project files without leaving picos.
- Open common text files quickly.
- Make small edits safely.
- Avoid accidental destructive filesystem changes.
- Prepare for remote files through the same mental model as local files.

If a feature is impressive but not useful in repeated terminal work, it does not belong in v0.3.

## Scope

### v0.3.0 Included

- `Files` workspace in the TUI.
- Local file provider with read-only browsing and file reads.
- DOS-style CLI commands:
  - `picos pwd`
  - `picos dir [path]`
  - `picos ls [path]`
  - `picos type <path>`
  - `picos cat <path>`
- Text file viewer for plain text, Markdown, JSON, logs, config files, and TypeScript/JavaScript source.
- Editor buffer model for text files.
- Confirm dialog before writing file changes.
- Dialog primitives:
  - confirm dialog
  - input dialog
  - error dialog
  - progress dialog
  - command/action palette dialog
- File action metadata in the existing permission model.

### v0.3.0 Deferred

- Delete, move, copy, rename as enabled write actions.
- Binary file editing.
- Recursive bulk operations.
- Secret/password storage.
- Real SFTP transport.
- Vim/emacs-level editor behavior.

### v0.3.1 Included

- SFTP-like remote provider behind the same `FileProvider` API.
- Remote profile inventory.
- Key-path based auth first.
- No password persistence.
- Remote read/list first, write behind explicit confirm.

## User Experience

### TUI Files Workspace

The Files workspace keeps the existing OS shell layout:

```txt
WORKSPACES          FILES                         INSPECTOR
> Files             /Users/bonjin/project         selected: README.md
  Editor            > README.md                   type: markdown
  Network Tools       package.json                size: 12 KB
  Actions             src/                        mode: read/write confirm
                     tests/

EVENT LOG
[ok] opened README.md
[warn] file has unsaved changes
```

Expected keyboard behavior:

- `j/k`: move selection in file list.
- `enter`: open directory or view file.
- `h`: go to parent directory.
- `e`: open selected text file in editor.
- `s`: save editor buffer only after confirm dialog.
- `esc`: close dialog or editor focus.
- `/`: filter current listing.
- `:`: command/action palette.

### CLI File Commands

`picos` should feel useful even outside TUI:

```bash
picos pwd
picos dir
picos dir src
picos ls src
picos type README.md
picos cat package.json
```

Output should be predictable and script-friendly. `dir` can be DOS-flavored, but it should not include decorative UI.

### Editor Flow

v0.3 editor is intentionally modest:

1. Read a text file into an editor buffer.
2. Track dirty state.
3. Show a confirm dialog before writing.
4. Write only through provider API.
5. Emit event log entry after save.

The first editor can support line-based navigation and basic insert/delete text operations. Advanced editing can come later.

## Architecture

### Core File Provider

Create `src/core/files.ts` with a provider-neutral API:

```ts
export type FileProviderKind = "local" | "sftp";

export type FileEntry = {
	name: string;
	path: string;
	type: "file" | "directory" | "symlink" | "unknown";
	size?: number;
	modifiedAt?: Date;
	readonly: boolean;
};

export type FileReadResult = {
	path: string;
	content: string;
	encoding: "utf8";
	truncated: boolean;
};

export type FileProvider = {
	kind: FileProviderKind;
	pwd(): Promise<string>;
	list(path: string): Promise<FileEntry[]>;
	read(path: string, options?: { maxBytes?: number }): Promise<FileReadResult>;
	write(path: string, content: string): Promise<void>;
	stat(path: string): Promise<FileEntry>;
};
```

v0.3.0 implements only `local`. `sftp` exists as a type and disabled action, not as transport.

### Path Safety

Local file operations should use Node/Bun filesystem APIs, not shell commands. No `safeExec()` is needed for local file reads because no process is spawned. SFTP transport later must use a library wrapper, not shelling out to `sftp`.

Safety rules:

- Resolve paths before display and actions.
- Do not follow symlinks for write until explicitly designed.
- Refuse to read files above a max byte size unless user confirms.
- Refuse to open binary files in the text editor.
- Writes require confirm dialog.
- Delete/move/copy stay locked in v0.3.0.

### Dialog System

Create `src/tui/dialogs.ts` for pure dialog state:

```ts
export type DialogState =
	| { type: "none" }
	| { type: "confirm"; title: string; message: string; confirmLabel: string }
	| { type: "input"; title: string; value: string; placeholder?: string }
	| { type: "error"; title: string; message: string }
	| { type: "progress"; title: string; message: string }
	| { type: "palette"; query: string; actions: string[]; selectedIndex: number };
```

The dialog layer owns keyboard focus while open. `esc` closes non-progress dialogs. Confirm dialogs must require an explicit positive key, such as `y` or `enter` on the focused confirm button.

### Editor State

Create `src/core/editor.ts` for pure editor buffer logic:

```ts
export type EditorBuffer = {
	path: string;
	original: string;
	content: string;
	cursorLine: number;
	cursorColumn: number;
	dirty: boolean;
};
```

Core editor logic should be tested without Ink:

- create buffer
- insert text
- delete text
- move cursor
- update dirty state
- reset after save

### TUI Integration

Add screens:

- `files`
- `editor`

The `Files` screen uses the local provider to show entries. The `Editor` screen shows the current buffer and uses dialogs for save confirmation.

The existing `Actions` panel should add:

- `files.list`: read, enabled
- `files.read`: read, enabled
- `files.write`: write, disabled until confirm flow is implemented
- `files.delete`: destructive, locked
- `remote.sftp.connect`: read/user, disabled until v0.3.1

## SFTP-like Remote Design

v0.3.1 should not be a separate UX. It should reuse Files and Editor.

Remote profile shape:

```json
{
  "name": "prod",
  "host": "example.com",
  "port": 22,
  "username": "deploy",
  "keyPath": "~/.ssh/id_ed25519",
  "root": "/var/www"
}
```

Rules:

- No password storage.
- No automatic host key bypass.
- No destructive remote operations until preview/confirm/audit exists.
- Remote writes require confirm and visible target host/path.

## Error Handling

File operations should produce useful errors:

- not found
- permission denied
- path is directory
- unsupported binary file
- file too large
- write confirmation required
- remote profile unavailable

The TUI should show errors in an error dialog and append the event log.

## Testing

Unit tests:

- local provider lists files and directories from a temporary fixture.
- provider reads text and rejects oversized reads by default limit.
- binary detection rejects binary editor opens.
- editor buffer tracks dirty state.
- dialog reducer opens, confirms, cancels, and preserves focus.
- action catalog keeps write/destructive file actions locked.

CLI tests:

- `picos dir` formatter output.
- `picos type` formatter output.
- invalid path errors.

Manual checks:

- Open Files workspace.
- Navigate into a directory.
- Open README in viewer.
- Edit a small temp file.
- Confirm save.
- Verify locked delete/move/copy actions cannot run.
